# How Earning Works

Pollen rewards contributors for high-quality, diverse usage data. The more informative your sessions are, the more you earn.

## The basics

1. **Contribute data** — Use Claude Code with the Pollen hook active
2. **Sync to Neon** — Run `pollen sync` to push your local data
3. **Get scored** — Each epoch, your contributions are scored using the Information Value Score (IVS)
4. **Claim tokens** — After an epoch completes, claim your POLLEN tokens

## Information Value Score (IVS)

Not all data is equally valuable. A session where someone debugs a complex authentication issue across multiple tools is more informative than one that asks a single question.

The IVS considers:

- **Topic diversity** — covering different topics increases your score
- **Session depth** — longer sessions with more tool usage score higher
- **Arc completeness** — sessions with clear intent → outcome arcs are more valuable
- **Uniqueness** — contributing data in underrepresented areas scores a bonus

## Revenue sharing

POLLEN token holders earn a share of revenue generated by the [Trends API](/docs/developers/trends-api). When developers pay for API access (via [x402 micropayments](/docs/developers/x402)), that revenue flows back to contributors proportional to their token holdings.

```
API revenue → POLLEN holders (pro-rata) → USDC claims
```

Claim your revenue share:

```bash
npx @pollen/cli claim --revenue
```
